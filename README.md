# 🎲 Tavern Dice · 酒馆战斗掷骰

用于 SillyTavern / TauriTavern 的当前场景回合制战斗扩展。正文模型生成或读取战斗场面，战斗模型负责结构化与行动决策，本地引擎负责掷骰和数值结算。

## 安装

在酒馆「扩展 → 安装扩展」填入 `https://github.com/ROSE12545412/pooh`。也可将完整扩展目录放入酒馆第三方扩展目录并启用，刷新或重启酒馆后点击悬浮骰子打开面板。部署时保留源码、样式、assets图片与扩展清单，不要只复制入口脚本。

## 手机与界面

界面采用博德之门3启发的黑曜石、古铜金边与羊皮纸文字色，不使用游戏素材或外部字体。手机（宽度不超过600px）使用紧凑留白、可横滑标签栏、三列阵容卡（超窄屏两列）、单列技能／骰子操作台。主要操作保留40–44px触控高度，输入字号16px避免移动浏览器自动放大。面板随可用视口和软键盘调整，手机布局不覆盖桌面保存的窗口位置；弹窗与长表格独立滚动。设置页可分别调整主悬浮窗宽高／手机占屏比例，以及悬浮骰子40～128px大小，并恢复默认。

## 开始一场战斗

1. 在「设置」中配置并测试「战斗模型」。可以使用连接配置、酒馆助手、兼容 OpenAI 的直连端点或主连接。
2. 正文模型默认使用当前聊天主连接。正文通道的独立读取与测试依赖酒馆助手；也可选择已配置的战斗模型。
3. 在战斗页填写可选的战况补充，点击「开始战斗」。插件发送场景指令，等待正文生成结束，然后解析当前参战者并开战。
4. 选择技能与目标，或使用自动行动。模型可以选择行动；命中、伤害、资源和状态变化由本地引擎结算。
5. 战斗结束后检查结果，再主动发送战斗结算，让正文继续叙事。

也可先把场景指令写入输入框自行检查后发送，或从已有剧情读取场面。新场景的参战者由本次场面决定。

自动开战会同时核对正文结束事件、宿主的实时生成状态与本次发送后的新回复；宿主漏发结束事件时，只要已确认生成停止，仍会继续解析。流式输出中的短暂停顿不会触发解析，旧楼层不能冒充本次场景。终止生成、切换聊天或等待超时会停止开战并清理等待状态。

开战解析、战斗启动并确认聊天元数据保存成功后，自动安全删除本次开战提示词与对应正文回复两楼，减少上下文占用。清楼兼容酒馆助手与宿主原生删除接口，无需手机额外安装酒馆助手；按倒序删除，避免先删提示词后回复索引移位。解析／启动／保存失败时保留；两楼内容改变、后面追加消息、切换聊天或缺少安全删除接口时也不冒险清理，会明确提示。

## 死斗留手与阻止队友

死斗中，玩家或队友本次直接攻击可能造成致命伤害时，会在掷骰和扣费前逐目标询问。玩家可「留手」，队友攻击可「尝试阻止」；也可明确继续攻击。关闭、ESC、暂停或终止均暂停整次行动，不默认继续、不扣资源。只是可能致命才询问，实际未命中或非致命时不会提前移除目标；切磋以及未来回合的持续伤害不触发这次询问。

玩家留手在实际致命命中时直接生效；阻止队友需真实掷 `d20 + 玩家当前装备／状态命中净修正` 对抗 DC10，天然1失败、天然20成功，失败仍按原攻击结算。成功时敌方保留1点HP、丧失战斗能力并退出至独立观战席，不再参与行动、受伤、治疗或状态结算，不算阵亡。群体攻击逐目标询问并分别结算，预判不消耗战斗随机数。观战状态随战斗保存，所有留手／阻止成功失败记录均进入战后结算供正文续写。

## 战斗界面

- 悬浮入口使用透明背景的骰子本体，不带圆形底座。点击打开面板，按住拖动可更换位置并保存；拖动后松手不会误打开面板，图片也不会被浏览器拖走或选中复制。鼠标、触屏和 Enter／空格键均可操作，缩小窗口时入口会保持在可见范围内。
- 红色生命球和蓝色魔量球通过液面显示剩余比例；点击圆球展开 HP、MP、攻击、护甲、速度、闪避、装备和状态，再点收起。
- 双方都有小头像，未设置时显示姓名首字。点击头像可上传 PNG/JPEG/WebP/GIF，单张不超过 5 MB。
- 头像保存在当前浏览器的 IndexedDB，按角色卡或群聊加人物名复用，刷新和下一场战斗仍可读取。头像不包含在聊天 JSON 导出中，清除站点数据会移除图片。
- 我方先排列玩家，再排列队友；人数较多时自动换行。技能区位于骰子旁边，窄屏上下排列。
- 骰子下方显示「判定总值／目标难度」，随后是「骰点＋加成＝总值」和各项技能、装备、状态的数值来源。负面修正单独标红；天然暴击或大失败覆盖普通比较时注明规则。显示使用本次行动快照，切换到下一角色后不改写出手人。
- 自定义多骰显示实际骰子组合、公式与输入值；概率模式显示随机值与命中率，保留该模式独立的天然骰规则。伤害与命中分别结算，旧记录缺少明细时直接说明。
- 单体技能与普通攻击先选择技能，再点击合法目标按钮或对应角色卡；即使只有一个目标也会等待确认。治疗可选择自身或队友。AOE、自身与随机技能直接按各自范围执行，不能把群体技能缩成单体来绕过衰减；上传头像和展开属性不会触发攻击。

### 技能范围、控制与持续效果

开战指令要求逐条输出：`技能名｜范围｜效果类型｜威力｜消耗｜持续回合｜回合豁免DC｜效果说明`。范围与效果独立，可明确组合「伤害+控制」「伤害+持续伤害」「骰点减益」；纯控制、纯持续伤害不会被补成一次直接攻击。每人至少3个符合设定的技能，不截断更多技能；旧五列场景仍可读取。

- **AOE伤害衰减**：默认每目标伤害乘以 `max(0.35, 1/√目标数)`，在威力换算、护甲结算后应用一次。持续伤害的挂载数值同样衰减；控制难度、持续回合和明确的骰点减益不衰减。自定义规则选择不衰减或线性衰减时沿用其配置，日志显示实际系数及前后数值。
- **控制**：先通过技能命中判定才挂上。受影响者每次自身回合开始，额外掷 `d20 + 当前装备/状态判定修正` 对抗该效果DC；失败跳过这一手，成功可以行动但不永久解除后续控制。默认DC10，明确数值可为2～30。
- **持续伤害**：同样先命中。每个持续伤害状态在目标回合开始独立掷一次豁免骰，失败按状态数值与层数扣血，通过则本次不扣血；真实骰点、总值、DC与扣血结果均有记录。
- **骰点减益**：命中后按明确的负值扣减，如「目标判定-2」。行动前显示来源、负值和装备/状态净修正，结算时进入使用 `hitBonus` 的命中公式及控制/持续伤害豁免。自定义命中公式未使用该变量时会明确提示，不谎称已扣入；技能自身施放加值与施加给目标的减益分开处理。

控制和持续伤害豁免均为天然1失败、天然20成功。持续回合按受影响者自己的回合计算，1回合效果覆盖这一手后才到期；刷新存档不会重复掷已处理过的回合开始骰。旧存档缺少技能分类时不凭名称猜造新机制，建议重新生成场景。

## 战斗结果衔接正文

点击「发送给正文模型续写」会将完整结算写入酒馆输入框，并自动点击原生发送按钮，立即启动正文生成，而不是只添加一条用户消息。正文正在生成时拒绝重复发送；短时间重复点击也不会重复发出。若发送按钮缺失或禁用，会保留输入框文本并明确提示手动发送，不会把它标记为已发送。

## 战前装备（可选）

战斗页的开战按钮上方提供四个下拉抽屉，自动列出自定义库条目。未润色条目可查看，但须先回填可执行规则才可携带。选择会保存，只作用于下一场战斗，不修改正在进行的战斗。

1. **技能**：可多选，支持全选已润色技能或清空；未选项不覆盖正文技能。
2. **武器**：单选一件自定义武器，或选择「使用正文武器」。
3. **防具**：单选一件自定义防具，或选择「使用正文防具」。
4. **饰品**：最多选择两件不同名自定义饰品；可「不佩戴」明确移除正文饰品，也可恢复使用正文饰品。选择自定义饰品时替换正文饰品，两件自定义的实际加值各应用一次。

库中的原「以后携带」选择与此处同步，武器／防具互斥、饰品最多两件；未选择自定义武器／防具时沿用正文；饰品默认沿用正文，但明确选「不佩戴」后会移除正文饰品，须选「使用正文饰品」恢复。

## 自定义技能与装备库

在「🎒 自定义库」选择技能、武器、防具或饰品，填写名称和作用说明并保存。可以点击单条润色，或用独立的「选择润色」复选框单选／多选后发送所选条目。插件参照开战流程，把润色提示词写入酒馆聊天输入框并发送，让正文模型结合当前世界观、剧情、人设和主角实力逐项润色；正文输出结束后，再由「战斗模型」（P2）回收为可执行 d20 规则，校验全部条目后一次回填。正文请求带最近1～60条剧情及当前玩家战力，不通过静默正文调用替代聊天流程。

回填成功并保存后，自动核对并删除本次润色请求与对应正文回复两楼。中断、切换聊天、条目版本变化、回收失败或保存失败时保留楼层；两楼被修改、后面插入其他消息或缺少安全删除接口时不冒险删除，会提示规则已回填但清楼未完成。保留用户原始描述，完整规则及优点、代价和平衡依据可展开查看。未通过规则校验的结果不会成为默认攻击；修改名称、类型或描述后需重新润色。

- 润色不会自动勾选。勾选项只应用于下一场战斗中唯一确认的玩家，修改库不改变正在进行的战斗。
- 同名技能、自定义装备与剧情装备同名或同标准槽位冲突时，自定义优先替换，不重复叠加。未勾选或未润色条目不覆盖正文；武器／防具只选一件，同名技能或饰品不重复叠加，两个不同名自定义饰品允许同时生效。
- 库装备的明确平加值由本地应用一次；支持攻击、护甲、速度、闪避和命中，不执行描述中未实现的反伤、吸血或条件触发效果。
- 装备攻击优势真实掷2d20取高，劣势取低；防御优势让来袭者取低，防御劣势让来袭者取高。多个同向来源不加骰，相反来源抵消，天然1/20以保留骰为准；逐目标明细保留实际骰点及来源。复杂多骰/概率等不兼容的自定义公式沿用原规则并提示未应用，不能伪报优势生效。

**手动触发保持不变**：开战只建立战场与先攻并等待玩家行动；换人只修改控制权、清理旧行动计划并暂停，不改变先攻、血蓝、日志或随机数。打开/重绘界面不会自行出手；提交新角色合法行动后，才按先攻处理前置AI阶段及本次行动。敌方AI看到全体合法目标及稳定ID；本地兜底按照战况选择，同分用可重放随机数，不因名单首位固定锁定某人。

## 口嗨与累计说服

在设置的「💬 口嗨模型」中单独配置连接，选择最近上下文楼层数（1～60）。自己的回合可在头像区上方选择存活的敌方角色、输入台词并发送；玩家、友方与已倒下角色不会进入说服列表。敌方成功换到我方后立即从列表移除，没有可选敌方时禁用发送。普通口嗨调用一次模型，不消耗战斗行动，不写入聊天楼层。

开战场景会逐人评估其对敌方角色的定向魅力（0～100），依据双方关系、好感与立场，人物详情可查看数值及依据。这不是颜值或固定成功率，双方数值可以不同，未评估不会显示成0。

口嗨模型先识别**本次话语**是否真的在劝说。闲聊、调侃、表达亲近和单纯放狠话只生成对白，不更新说服进度，也不调用条件评估或重新弹出旧检定。不能仅因以前劝说过，就把后续每句话都算作劝说；意图字段缺失或无效时也只按普通口嗨处理。

亲情、友情、爱情、承诺与眼下的分队都交给口嗨模型结合人设、上下文和此前对话判断；不会仅因人物在敌方、战斗是切磋或死斗就固定拒绝或答应。真正针对原有顾虑补充承诺或理由仍可算作继续劝说，不必每句重复换边邀请；是否属于劝说由模型理解语境，不靠本地关键词判断。

累计动摇、已接受的条件、剩余顾虑与分析依据按「说话者＋目标NPC」**保存在后台**，口嗨区只展示对白，不展示进度条、记忆摘要或分析面板。累计值不是成功率，不按消息次数自动加分；普通口嗨、刷新、暂缓、检定失败和后续回复漏写进展都不会清空已有动摇。旧存档没有该记录时从下一次真实劝说开始记录，不凭旧台词猜分数。

只有本次被识别为劝说，且已有部分或完全动摇时，才再次调用同一个口嗨模型评估当前难度，显示简洁的「现在掷骰／继续劝说」确认。分析理由仍留在后台。有动摇后不再另设一道招降资格门槛，尚存顾虑体现在DC里；缺少有效DC时提示评估错误，保留进度。回复完成本身不会掷骰或改变阵营。

检定使用本地 `d20 + floor((魅力-50)/10)` 对抗模型给出的 DC 5～30，天然1失败、天然20成功。确认前可看到DC、魅力加成、最低成功骰点和真实成功率；例如DC15、加成+3需要d20至少12点，成功率45%。「继续劝说」保留进度、当前条件和输入草稿；「现在掷骰」才进行一次检定。每份条件只能使用一次，失败后可继续劝说获得新条件。旧存档缺少定向魅力时由条件模型估值，不需要重建全局战力表。

玩家确认且检定成功后，对方在本场战斗转为我方，保留伤势、资源与技能，后续交给队友行动流程；这项机械变更不自动宣称永久背叛原关系。旧行动计划失效重算，最后一名敌方换边会结束战斗。口嗨对话保存在独立历史中，供口嗨模型续聊，同时显示在战斗日志里。

结算区有「口嗨记录：一同发送／不发送」按钮，默认不发送；开启后可预览附带的完整对话，再点击「发送给正文模型续写」一并发送。切换不会自动写入聊天，也不会覆盖手动编辑的战斗文本；选择随本场结算保存。无论是否附带口嗨，魅力检定与实际阵营变更都会保留在结算中。旧战斗存档中的口嗨会在恢复时移到独立历史，避免对白中的伤害或治疗措辞混入引擎事实。

可选定一本人设世界书：仅读取目标人物的精确标题或主关键字条目。缺少时根据当前场景及所选剧情整理人设，追加条目且不覆盖现有内容；新增条目默认关闭自动注入，供口嗨显式读取。未选书或关闭读取则不读写世界书，也不会新建整本书。

## 模型与规则

| 职责 | 执行方 |
| --- | --- |
| 生成或读取当前场景 | 正文模型 |
| 提取参战者、属性、技能与状态 | 本地场景解析与结构化 API |
| 选择行动和目标 | 战斗决策 API 或本地策略，取决于设置 |
| 掷骰、伤害、资源与回合推进 | 本地战斗引擎 |

设置中的「战斗模型」供结构化和决策使用。内部仍可能使用 `p2` 配置键以兼容现有连接设置。

战斗规则支持公式配置；缺少可用规则时采用通用 d20：`d20 + (Aim - 100) / 10 + hitBonus` 对抗目标的有效 `Evasion`。单颗命中骰与天然值使用同一次掷骰。日志保留种子与计算过程。同一版本、初始状态、规则、随机种子和行动序列可复现机械结算；模型生成的行动本身不保证重复一致。规则或随机数消耗方式变更后，跨版本重演相同种子可能产生不同轨迹。

新场景明确记录基础属性与装备、临时状态的独立数值。仅明确 `attributeBasis: base` 才额外叠加装备；旧 JSON 未说明属性是否包含装备时保持原口径，并在检定明细提示。显式状态修正优先于文字关键词，命中加值不同时提高伤害威力；未写明数值的定性描述不会被伪造成固定加值。

## 存档与聊天

- 模型配置和界面偏好保存于酒馆扩展设置。
- 当前场景、战斗进度与日志随聊天 metadata 保存，切换聊天时恢复对应战斗。
- 切换聊天会停止自动推进；继续前请检查当前战斗。
- 设置页保留数据导入、导出和清空本聊天数据入口。
- 战斗过程显示于插件面板；生成场景和主动发送结算会在聊天中产生消息。

## 命令

| 命令 | 用途 |
| --- | --- |
| `/dice-init [战况补充]` | 生成当前战斗场景并开战 |
| `/dice-roll start` | 使用同一场景生成流程开战 |
| `/dice-roll` | 让当前行动单位自动行动一次 |
| `/dice-status` | 查看当前战斗单位、HP 与回合；没有战斗时显示当前场景 |
| `/dice-panel` | 打开或收起面板 |

## 常见问题

**正文通道测试失败**：检查酒馆助手是否已启用，或切换到配置好的战斗模型，再使用通道测试查看具体原因。

**等待场景超时**：确认正文回复是否完成，并查看日志。已有可用场景时，可以从已有剧情读取并开战。

**结构化或行动选择失败**：检查战斗模型地址、密钥、模型名与响应格式，查看日志中的接口或解析错误。

**数值不符合预期**：检查场景文本中的属性、技能威力口径与掷骰规则。模型提取可能有误，结算前应核对关键数据。

## 发布与素材

仓库根目录应直接包含扩展清单和入口，不要再套一层目录。源码使用 MIT 许可证；第三方骰面素材遵循 [独立授权](<assets/d20/LICENSE.txt>)，不作为独立素材包再发布。悬浮骰子图由项目作者提供并确认可公开分发。

上传前运行 `npm run verify`。`.gitignore` 已排除日志、缓存与本地私密配置；网页拖拽上传和手动 ZIP 不会应用该规则，请勿混入 `*.log`、聊天导出、API密钥或本机配置。日志和导出可能含剧情及接口信息，提交问题前需脱敏。首次发布版本为1.0.0，发布 tag 应与清单及包版本一致。

安装副本测试需指定目录：`npm run smoke:installed -- "<安装的扩展目录>"`，或设置 `TD_INSTALLED_DIR`。这项测试会在假 DOM 驱动指定副本，不等同于真实酒馆／手机视觉验收。
