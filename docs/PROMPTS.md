# 当前场景与战斗提示词

提示词服务于场景生成、场景读取、结构化与行动决策。实际输出格式以源码中的提示词、解析器和校验逻辑为准。

## 场景生成

用户点击开始战斗或使用开战命令后，插件向正文模型发送当前战斗场景请求。请求结合用户补充要求、当前角色与玩家信息，要求提供：

- 当前实际参战者及其阵营，明确玩家操控的角色。
- 位阶与人物特征。
- 当前生命、魔力及可用属性。
- 技能、武器与装备。
- 临时增益、减益与场景限制。

参战范围应限定于本次场面。角色名称与玩家身份从当前聊天获取，不写死任何角色卡专用名称。

## 读取与结构化

已有剧情可以直接作为场景读取来源。结构化阶段的输入是当前场景报告及相关战斗上下文，输出是可由战斗引擎消费的参战单位与规则数据。

清晰的场景格式可由本地解析处理；需要模型提取时使用设置中的战斗模型。应保留显式数值、技能费用与限制，避免擅自改变量级。缺少的信息应明确说明并由归一化或规则兜底处理。

结构化结果必须经过解析与校验。失败信息应包含可操作的原因；用户可检查模型通道、重读当前场景或修改补充要求。

## 战斗行动决策

决策请求使用当前战斗状态，包含行动者、可用技能、目标、资源、冷却、状态和场景限制。模型负责选择行动及目标，并解释战术意图。

决策必须引用当前单位与合法技能，服从行动次数、目标阵营、资源和冷却约束。模型输出不能直接覆盖 HP、骰点或最终伤害；这些由本地规则引擎计算。决策失败时按控制器配置处理本地回退或向用户报告。

## 自定义库润色

单条或批量润色先将所选名称与描述发到真实聊天，让正文结合世界观、剧情和玩家实力完成设定；生成结束后战斗模型将回复转换为严格的可执行规则。所有条目校验通过才一次回填，不能将正文中的自由描述直接当作引擎代码执行。已选携带内容同时加入开战约定，自定义冲突优先，未选不覆盖正文。

## 结果发送

发送给正文的结算应描述已经完成的机械结果，包括关键行动、资源变化、状态与胜负，并要求正文在这些结果基础上继续叙事。由用户主动发送，不逐回合自动写入聊天。

## 修改与验证

修改提示词时同步检查解析器与调用方，覆盖这些情况：

1. 场景中玩家身份与阵营明确。
2. 当前参战者不混入上一场的离场角色。
3. HP、MP、技能威力与费用保留原有口径。
4. 不完整、带围栏或格式异常的模型输出得到明确处理。
5. 决策目标合法，失败不会跳过规则引擎直接改写战斗结果。
6. 模型调用取消、超时和聊天切换不会把结果写到错误聊天。

运行 `npm run verify`，并在实际酒馆检查完整开战与发送结算流程。测试数量以运行结果为准。
